01 — Editor · authoring surface

The header had four publishing concepts competing flat: Listed/Unlisted, Publish changes, a locked slug, Copy link and View. Now it's one status pill, one button, one menu. Save state stopped being a floating string and moved into the pill, which is also where a failed save has to appear — currently a dozen actions fail silently. The step rail is the same filmstrip component as the reader, so you build it once.

Adding a step moved out of the rail and into the canvas. Hover between any two steps for an insertion point, or use the button at the end with ⌘⏎. The rail is now purely a map — it navigates, it doesn't act. Note this is a different job from Split: Split means "this step covers two things," insert means "I missed a step entirely."

02 — Publishing · one button, one menu

Every competitor stores a draft and a published version separately and gives you a way back — Help Scout puts Unpublish and Discard changes in a dropdown beside the primary button, which is where people already look. You currently have neither: visibility can never return to draft from the UI. "Listed / Unlisted" is also renamed — nobody outside this category knows what unlisted means, but everyone understands "hidden from search and browsing."

03 — Preview and the publish moment

Zendesk and Help Scout both open preview in a new browser tab you have to manually refresh after every edit; Intercom has no preview and tells you to publish as unlisted instead. Your reader is already a component in this same app, so an in-place toggle costs nearly nothing and beats all three. And "You're live!" currently dead-ends — this is where theming should be offered, which is what §5 always said and what the build never did.

04 — Theming

Header treatment goes first because it's the largest visual lever — and it's the fix for a brand colour that turns the band grey. The preview gains a view switcher and a device switcher, which is what Intercom does; yours is pinned to the home view only, so nobody can check what an article looks like. Sample content is now labelled rather than passed off as real — right now fake articles render silently and stay if the fetch returns nothing. Save moved to a sticky bar with somewhere for a failure to appear; today a failed save renders nothing at all.
